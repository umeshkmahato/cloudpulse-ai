# CloudPulse AI
Real-Time Intelligent Cloud Operations & Predictive Resilience Platform (interview-focused POC).

- GCP project: `cloudpulse-ai-poc` | Preferred region: `asia-south2` (verify per service in Phase 2)
- Principle: **local-first, zero-cost by default; every billable GCP resource needs explicit approval.**

## Run and validate
See [doc/RUN-AND-VALIDATE.md](doc/RUN-AND-VALIDATE.md) for prerequisites, both run paths (kind or Compose), the validation checklist with expected results and the list of what is not validated.
Quick path: `scripts/k8s-up.sh`, then `scripts/k8s-verify.sh`, `scripts/k8s-security-verify.sh`, `scripts/k8s-remediation-e2e.sh`, and `scripts/ci-local.sh`.

## Phase 1 quick start (deferred: only when enabling GCP, personal account only)
```bash
gcloud auth login && gcloud auth application-default login
gcloud config set project cloudpulse-ai-poc
./scripts/phase1-validate.sh | tee phase1-report.txt
```
Never commit credentials, service-account JSON or Terraform state (see `.gitignore`).
Local demo logins are generated by `scripts/k8s-up.sh` into `.run/identity-credentials.txt` (git-ignored); roles: viewer, operator, admin.
Generated/test data in this project is always labeled as synthetic, never as real GCP telemetry.
